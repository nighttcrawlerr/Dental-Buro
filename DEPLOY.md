# Выкладка сайта

Сайт собирается в Docker-образ и запускается на любом хостинге, который умеет
Docker и даёт управляемый PostgreSQL. Серверы — только в РФ: в базе лежат
персональные данные пациентов (152-ФЗ, ст. 18, ч. 5).

Подходят Timeweb Cloud, Selectel, Yandex Cloud. Проще всего — хостинг, который
сам собирает образ из GitHub по каждому пушу (у Timeweb Cloud это «Приложения»).

## Что понадобится

1. **PostgreSQL** на том же хостинге (управляемая база: резервные копии и
   обновления — забота хостинга). Нужна строка подключения.
2. **Приложение из Dockerfile** этого репозитория, порт **3000**.
3. **Переменные окружения** — ниже.
4. **Домен** — можно позже: сначала проверяем сайт на временном адресе хостинга.

Аккаунты хостинга, домена и Метрики регистрируются **на клинику**, разработчику
выдаётся доступ. Иначе при смене подрядчика клиника остаётся без своего сайта.

## Переменные окружения

Часть переменных нужна **при сборке**: страницы, `robots.txt` и `sitemap.xml`
собираются заранее, и значения вшиваются в них в этот момент. В панели хостинга
их задают как «аргументы сборки» (build args). Если поменять — нужна пересборка,
простого перезапуска мало.

| Переменная | Когда | Что это |
|---|---|---|
| `SITE_URL` | сборка **и** запуск | Адрес сайта без слеша: `https://dentalburo.ru`. Пока не задан — сайт закрыт от поисковиков |
| `SITE_INDEXING` | сборка | `off` — сайт на домене, но закрыт от поисковиков (пока на нём заглушки). Пусто — открыт |
| `NEXT_PUBLIC_YM_ID` | сборка | Номер счётчика Яндекс Метрики. Пусто — Метрика и плашка cookie выключены |
| `DATABASE_URL` | запуск | Строка подключения к PostgreSQL. **Обязательна** |
| `ADMIN_PASSWORD` | запуск | Пароль входа в `/admin`. **Обязателен** |
| `ADMIN_SESSION_SECRET` | запуск | Секрет подписи сессии, ≥ 32 символов: `openssl rand -base64 48`. **Обязателен** |
| `TELEGRAM_BOT_TOKEN` | запуск | Токен бота. Без него заявки сохраняются, но уведомлений нет |
| `TELEGRAM_CHAT_ID` | запуск | id группы для уведомлений |

Если обязательной переменной нет, сервер при старте пишет в лог, какой именно,
и не принимает запросы — проверка здоровья хостинга это покажет.

## Порядок

1. Создать базу PostgreSQL, скопировать строку подключения.
2. Создать приложение из этого репозитория (ветка `main`, Dockerfile в корне).
3. Вписать переменные. `SITE_URL` пока — временный адрес, который выдал хостинг.
4. Указать проверку здоровья: `GET /api/health` → 200.
5. Запустить. Схема базы применяется сама при каждом старте — отдельно ничего
   запускать не нужно.
6. Проверить на временном адресе: главная, форма записи (заявка должна прийти в
   Telegram и появиться в `/admin`), вход в `/admin`.
7. Подключить домен, дождаться SSL-сертификата, поменять `SITE_URL` на домен и
   **пересобрать**.
8. Создать счётчик Метрики на домен, вписать `NEXT_PUBLIC_YM_ID`, пересобрать.
   Цели — в PLAN.md, шаг 9.2.
9. Добавить сайт в Яндекс Вебмастер и Google Search Console, отправить
   `https://домен/sitemap.xml`.

## После каждого пуша

Если хостинг собирает из GitHub — пуш в `main` и есть выкладка. Сборка идёт
несколько минут; пока новая версия не прошла проверку здоровья, работает старая.

## Подводные камни выбора

- **Регион — только Россия.** У Timeweb Cloud, например, есть и Нидерланды:
  и приложение, и базу создаём в Москве или Санкт-Петербурге.
- **Тип приложения — Dockerfile.** Готовый шаблон «Next.js» в «Приложениях»
  Timeweb собирает только статический сайт, а нам нужен сервер: заявки,
  админка, база. Поэтому приложение создаётся из Dockerfile этого репозитория.
- **Не всё на одном VPS.** Дешевле всего — один сервер, где и сайт, и база.
  Но тогда резервные копии, обновления и защита базы с персональными данными
  пациентов — на нас. Управляемая база стоит дороже, зато это делает хостинг.

## Что проверить у хостинга

- **Реальный IP посетителя.** Ограничение частоты заявок и попыток входа
  считается по заголовку `X-Forwarded-For`. Хостинг должен ставить его сам и
  перезаписывать то, что прислал браузер, — иначе ограничение легко обойти.
  Обычно так и есть, но стоит уточнить в документации хостинга.
- **Резервные копии базы.** Включены ли, как часто и сколько хранятся.
- **Одна копия приложения.** Ограничение частоты хранится в памяти процесса.
  На нескольких копиях оно работает хуже (у каждой свой счётчик) — для сайта
  клиники одной копии хватает с запасом.

## Как развёрнуто сейчас: Yandex Cloud

Сайт: https://dentalburoclinic.ru. Аккаунт облака — личный (клиника — семейный
бизнес), DNS — в reg.ru.

- **Виртуальная машина** `dental-buro`, зона `ru-central1-b`: Ubuntu 24.04,
  2 vCPU 50 %, 4 ГБ, статический IP `158.160.84.108`. Вход:
  `ssh deploy@158.160.84.108`. Код — в `~/dental-buro`, настройки — в
  `~/dental-buro/.env.production` (копия — в менеджере паролей).
- **Docker Compose**: приложение и Caddy (`docker-compose.yml`, `Caddyfile`).
  Caddy принимает 80/443, сам выпускает и продлевает сертификат Let's Encrypt,
  `www` перенаправляет на домен без `www`.
- **Managed PostgreSQL** `dental-buro-db`, класс `b2.medium`, один хост в
  `ru-central1-b`, без публичного доступа — виден только из сети облака.
  Резервные копии — ежедневно, 14 дней. Защита от удаления включена.
- **DNS в reg.ru**: A-записи `@` и `www` → `158.160.84.108`.

**Обновить сайт** после пуша в `main`:

```sh
ssh deploy@158.160.84.108 dental-buro/scripts/deploy.sh
```

Скрипт забирает код, пересобирает образ и перезапускает контейнеры. Смена
`SITE_URL`, `SITE_INDEXING` или `NEXT_PUBLIC_YM_ID` в `.env.production` тоже
применяется этим скриптом — они вшиваются при сборке.

**Открыть сайт поисковикам**, когда заглушки заменены реальным контентом:
убрать строку `SITE_INDEXING=off` из `.env.production` и запустить скрипт.

Если SSH с Mac не подключается, а сервер пингуется — порт 22 режет VPN.
Адрес сервера нужно добавить в исключения раздельного туннелирования.

## Локально

```sh
pg_ctl -D /opt/homebrew/var/postgresql@18 start   # база
npm run db:migrate                                 # схема
npm run dev
```

Образ целиком:

```sh
docker build --build-arg SITE_URL=http://localhost:3000 -t dental-buro .
docker run -p 3000:3000 --env-file .env.local \
  -e DATABASE_URL=postgres://$(whoami)@host.docker.internal:5432/dental_buro dental-buro
```
